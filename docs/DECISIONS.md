# Decisions log

Small implementation choices made during the build that `docs/PLAN.md` does not cover.
One line each: **decision** — why. The owner reviews these.

- **Plan decisions live in `docs/PLAN.md`** — this file is only for choices made while building.
- **Two npm workspaces (`packages/server`, `packages/ui`)** — keeps the Node bundle and the browser code apart; the UI imports only `protocol.ts` from the server.
- **Server runs TypeScript with esbuild; tests use vitest** — plan allowed either; vitest gives one runner for server and UI code.
- **Single file = esbuild bundle with the UI embedded as base64 (`__PHEME_ASSETS__` define)** — no extra files to copy besides `start-pheme.cmd`.
- **Copilot SDK (`@github/copilot-sdk` 1.0.34) bundles cleanly (1.3 MB) but only with `koffi` stubbed** — the SDK imports koffi (native FFI) at the top for its in-process mode, which Pheme never uses. The SDK's own 242 MB runtime package is NOT bundled; Pheme launches the user's own `copilot` (found on PATH or `COPILOT_CLI_PATH`) as the SDK's stdio runtime.
- **Finding: SDK 1.0.34 speaks protocol 3 and runtime 1.0.112; Copilot CLI 1.0.114 (current latest) speaks protocol 4 and the SDK refuses to connect** — `pheme doctor` and the engine now say so and name the CLI version to install (`COPILOT_CLI_TESTED`). Open question for the owner: pin the CLI, or add the ACP engine (see PROGRESS.md).
- **Finding: `copilot --acp --stdio` on 1.0.114 answers `initialize` with ACP protocol 1** — the plan's fallback engine is viable if the SDK skew becomes a problem. ACP has no custom tools or system-message append, so memory/skills would go through a small MCP server and a prompt preamble.
- **Real Copilot is not exercised by tests** — the SDK's own runtime authenticates via the `gh` login on this Mac, but a chat would spend the owner's Free quota, so that waits for the owner's go-ahead.
- **"auto" model = leave `model` unset in the SDK** — the CLI's own default is auto.
- **Cheapest review model heuristic** — first model whose id matches mini/haiku/flash/lite/nano, else `auto`; overridable in Settings.
- **Approval kinds** — reads and Pheme's own tools auto-allow; shell, write, url and mcp ask. "Allow for this chat" remembers by kind for the life of the server process.
- **Delta events are streamed but not stored** — only whole messages are persisted in the JSONL log.
- **Stale approval cards** — a card only shows while its chat is busy; after a restart it never appears.
- **Reviews run in a hidden chat that is deleted afterwards** — results appear only as a notice in the source chat.
- **Memory entries separated by `§`; skill `delete` moves to `skills/.archive`** — same convention as Hermes; deleting skills never destroys data.
- **Default port 7676, falling back to a free port** — stable bookmarks are impossible anyway because of the token.
- **Superseded 2026-11-28 by the hybrid port below.** The first UI pass was new code in Hermes's design vocabulary (the `--dt-*` token names, the Nous/GitHub palettes renamed Pheme/GitHub, system font stacks, the shadow/stroke approach).
- **CI uses `npm install`, not `npm ci`** — the Copilot SDK's per-platform optional packages make a lockfile written on macOS unreliable on Windows with `npm ci`.
- **Real-Copilot check done (3 short chats)** — custom tool, memory write and approval card verified; `tool_end` name now taken from the start event by id; repeated permission asks for one tool call are approved silently after the first Allow.
- **Job schedules: interval, daily (local HH:MM), once** — covers the plan without a cron parser.
- **Jobs run in a normal chat titled "Job: <name>"** — shows in the sidebar and keeps the transcript; job chats never prompt: allow or deny is fixed by `allowActions` at creation (reads always allowed).
- **Scheduler ticks every 30 s and advances `nextRunAt` before running** — a slow run is never started twice, and any number of missed runs collapse into one on start.
- **Subagents are both: an `agent` tool and saved profiles** — owner chose "both, parallel sessions first". The `agent` tool starts a separate engine session; saved profiles are also passed to Copilot as `customAgents` (infer on) so the CLI can delegate to them itself.
- **Sub-agent sessions get only `skill_view`** — no `agent` tool (no recursion), no memory or skill writes; a sub-agent cannot change long-term state.
- **At most 3 sub-agent sessions run at once** — protects the Free quota and the machine; extra calls wait their turn.
- **Sub-agent approvals appear as cards in the parent chat; Stop cancels the whole tree** — one place for the user to answer; child sessions are hidden chats kept for the transcript.
- **Profiles live in `~/.pheme/agents/<name>.md`, archived not deleted; runs in `agent-runs.json` (last 200)** — same conventions as skills. Profile changes apply to new chats, because Copilot gets them at session creation.
- **Real-Copilot check of subagents (2 chats)** — the model calls `agent` twice in one response and both run in parallel; a saved profile is delegated to through Copilot's own `task` tool and its `subagent.*` events become a card. The model sometimes adds a `name` argument to `agent`; it is ignored.
- **Themes generated by `scripts/gen-themes.mjs` from the Hermes preset table** — 11 themes (nous -> pheme, nous-alt -> pheme-alt). Hermes's `classic` skin is skipped (derived from a skin file, not a palette). Dark-only themes (midnight, ember, mono, cyberpunk, slate) show one mode. Per-theme web fonts are not loaded: the work laptop may block them, so every theme uses system font stacks for the UI. JetBrains Mono (SIL OFL 1.1) is bundled and served by Pheme for code, so it needs no external request.
- **Theme setting stays one string, "<theme>-<mode>"** — the Settings page shows two dropdowns (Theme, Mode); old values like `pheme-dark` and `system` still work.
- **Curator: stale = no skill_view and no edit for N days (default 90); consolidation by a hidden skills-only session (cheapest model); every change is verified against the files before it is reported** — archive, never delete.
- **Curator starts its clock the first time it ticks instead of running at once, then runs every 7 days while Pheme is open** — a fresh library has nothing to merge, and the run costs Copilot requests. "Run curator now" is on the Skills page.
- **Ctrl+K shows chats, pages, chat actions, settings toggles, themes and skills** — one action, one home: each command calls the same function as the visible button.
- **Real-Copilot check of reviews and curator (3 requests, seeded transcript, model "auto")** — all worked. The skill review put a user preference ("beginner") in a skill description, so the prompt now says user facts belong in memory only. Not re-run against real Copilot after that one-line change.
- **Stress-test fixes (round 1)** — malformed JSON now 400 and oversized body 413 (were 500); invalid chat ids are 404 (were 500); deleting a chat mid-turn no longer recreates its files; settings are range-checked (counts 1..1000, limits 100..100000, days 1..3650, strings <= 200 chars) — before, `0` or `-3` made reviews run on every turn; memory entries cannot contain `§`; a data file that is valid JSON of the wrong shape (e.g. `{}` for a list) falls back to defaults instead of crashing `/api/agents`; a torn last transcript line no longer swallows the next event; hidden (review/agent) chats cannot be sent messages.
- **At most 8 engine sessions stay open; a failed turn drops its session; deleting a chat closes it** — real Copilot sessions are processes/streams; they were kept until exit. An evicted chat resumes on its next message.
- **Long chats render the last 400 events (button loads earlier); sidebar shows 150 chats (search still finds all)** — a 6,000-event chat was 36,000 DOM nodes.
- **One Pheme per data folder (`pheme.lock` with the pid)** — two instances would both run scheduled jobs and reviews. A stale lock from a crash is replaced. `--port` is validated with a plain message.
- UI stress round: chat titles now strip markdown (titleFrom); sending your own message always scrolls to bottom; drafts flush on chat switch; offline detection is immediate on a refused connection and polls every 1.2 s while down; mobile drawer closes on Esc and manages focus; PHEME_TOKEN env var fixes the access key for tests.
- Markdown renderer is react-markdown + remark-gfm + highlight.js (20 languages); bundle grew to ~725 kB JS (accepted).
- Unknown CLI options are now errors (a typo like --fak used to start the real engine). THIRD_PARTY_LICENSES.txt now covers the UI dependency tree with full license texts (111 packages).
- Git panel (branch feat/git-review, not merged): per-chat projectDir passed to Copilot as session workingDirectory; changing it is refused mid-turn and drops the cached session. Git runs via execFile with --literal-pathspecs, 15 s timeout (90 s for commit hooks), output caps; paths validated, no shell. Commit server logic (stage exactly the ticked files, never commit on main/master/detached without a new branch, secret-looking files need explicit confirm, soft-reset undo only if HEAD unchanged and unpushed) is done and tested; the commit UI box is NOT built yet (a file-write step needed approval nobody could give overnight).
- Push/PR: push never forces and refuses main/master/trunk/detached; PR needs a pushed, up-to-date branch and uses `gh pr create --body-file -` (title/body never touch a shell). `gh` and `git` are told never to prompt. Without gh (or when signed out) the panel shows a GitHub compare link instead. Remote info polls once a minute (3 gh calls per poll). Tests use a local bare repo as origin and a fake `gh` on PATH (POSIX only; skipped on Windows).
- Commit box asks again whenever the file selection changes; secrets need a separate tick; Undo only for the commit just made, and only if HEAD is unchanged and unpushed.
- Per-chat model: chosen in a select next to the project bar; stored in the chat meta (absent = follow Settings default); refused mid-turn; drops the cached session so the next message uses it.
- Export: GET /api/chats/:id/export returns Markdown (tool output is summarised, never dumped; file name sanitised for Windows). Search: GET /api/search scans the newest 8 MB of each chat log with a 1.5 s budget, user and assistant text only, hidden chats excluded, one hit per chat; the sidebar debounces 300 ms and needs 2+ characters.
- Markdown renderer is lazy-loaded (own chunk, preloaded on idle; plain text shows meanwhile): main JS 735 -> 327 kB.
- Notifications are per browser (permission is), polled every 4 s even when the tab is hidden if enabled (browsers slow hidden timers to ~1/min). Only fires for chats you are not looking at.
- Backup = one gzip'd JSON file (no new dependency), allowlisted top-level names only, strict path validation, zip-bomb cap, restore defaults to "add missing, keep existing", always writes a safety copy to backups/ first (last 5 kept), refused while a reply runs. Sign-in is not included.
- Keybindings: six rebindable actions (palette, new chat, search, sidebar, prev, next); need Ctrl/Cmd or Alt; browser-reserved combos and Alt+1..9 refused; saved in localStorage; a corrupt or clashing save falls back to defaults per action.
- Playwright e2e (9 tests, fake engine, throwaway data dir and repo) runs in CI on Windows and macOS with Playwright's Chromium; locally PW_CHANNEL=chrome (Playwright's Chromium does not support macOS 13).
- Releases: pushing a v* tag runs .github/workflows/release.yml, which re-runs checks, verifies the tag equals package.json's version, builds, zips and publishes. Version bumped to 0.2.0.
- A failed commit (hook, missing Git identity) now rolls back completely: new branch deleted, original branch/detached HEAD restored, index restored exactly from a saved tree. Found by the first Windows e2e run, where the runner had no Git identity.
- Git commit/undo/push run one at a time per repo (queue), at most 6 git processes at once, identical status calls share one run, a stale index.lock gives a plain 409. Search: 2 scans at once, 6 waiting, else 429; identical queries share a scan; scan yields to other requests and stops when the page disconnects. Found by scripts/stress-scale.mjs (1500 chats, 5000 files, 7 MB diff): 2 simultaneous commits used to both fail with 500; 30 parallel searches took 5 s, now under 1 s; 50 parallel status calls 2.5 s, now 0.2 s.
- PR panel: `GET /git/pr` reads the branch's PR with `gh pr view` (checks, review, mergeability, size). Check links must be https; failing checks sort first; capped at 60 checks. A repo with no GitHub remote returns `pr: null`, not an error. The UI re-checks every 20 s only while checks are running and the tab is visible.
- Branches and stash live in gitbranch.ts. Switching never discards anything: git's own refusal becomes a confirm step ("set aside and switch"); if a switch fails after stashing the stash is popped back. Stashes are chosen by commit id, not position, so a list changed in another window cannot make us act on the wrong stash. Stash commands run without --literal-pathspecs because `git stash --include-untracked` breaks under it (it saved untracked files but left them in the folder). Branch names with control characters are refused (a NUL byte made Node throw a 500).
- Server tests that run real git get a 40 s timeout (15 s was too tight for a loaded Windows runner: a local `git push` timed out once, then the cleanup hit EBUSY).
- Context meter: the Copilot `session.usage_info` event is remembered during a turn and emitted once, as a `usage` event just before idle, so the log grows by one small event per turn. The UI reads the newest valid one (`role="meter"`). The fake engine simulates it (`[context:N]` in a prompt pushes it up).
- Attachments: images (PNG/JPG/GIF/WebP, 5 MB) and plain-text/code files (an explicit extension list, 512 KB, valid UTF-8, no NUL), 5 per message, 50 MB per chat. Validated by content, not by the claimed type or extension (a `.png` that is not a PNG is refused; SVG is refused). Names that look like secrets (.env, keys, credentials) are refused, checked on the raw name because cleaning strips a leading dot. Stored under <data>/attachments/<chat>/<uuid>.<ext> with 0600 perms; the stored file name is never taken from the client. Downloaded with the token header (blob URLs in the page, never a link with the token), served with nosniff and a sandbox CSP. Uploaded-but-unsent files are swept after 24 h; deleting a chat deletes its files. Images go to Copilot as SDK `blob` attachments. Text files go inside the message itself, in a labelled fenced block (the fence is longer than any backtick run in the file): a real-Copilot test showed the SDK `file`-by-path attachment never reached the model, even when it was allowed to use tools. The chat transcript keeps only what the user typed. All text files in one message together are capped at 512 KB. Upload happens when Send is pressed (same path for existing and new chats); on any failure the text and files go back into the composer. While a reply runs, text can be queued but attachments wait (the queue is text-only). Not included in backups (they are chat-local and can be large).
- Prompt library: saved in <data>/prompts.json; 200 max; names unique per scope (all chats, or one project) ignoring case; 80 / 20,000 character limits; project match ignores a trailing slash. Typing "/" at the start of the box opens the picker; Enter inserts (never sends) when something matches, otherwise the text sends as typed, and Esc dismisses it so a literal "/message" can still be sent. A damaged prompts.json is read as far as possible, never fatal. Inserting selects the first {{blank}}.
- Installable app: manifest + PNG icons (made from the SVG by scripts/make-icons.mjs, committed), no service worker on purpose (nothing can serve a stale UI or cache chats). The access key is also saved in localStorage so an installed window can start with no address; a rejected key is replaced by a newer one another window saved (once, no loop), otherwise the screen says to start Pheme again. Cost: the key now outlives the tab in that browser; it still changes at every Pheme start.
- `npm run verify` runs lint, typecheck, tests, build, smoke, both stress scripts (and e2e with --e2e) and stops at the first failure. Added after a gate was chained with `;` and a failing probe count was pushed anyway.
- Found by the first real-Copilot attachment test (2 requests): images worked, text-by-path did not (see above). The model also listed the stripes' order wrongly (red, blue, green for red, green, blue), which is model quality, not transport. The inline-text fix is covered by fake-engine tests only; it has not been re-run against real Copilot.
- **Default theme accent is the gold from the desktop screenshots (`#f7bb2d` dark, `#9a6800` light), not the blue Nous preset** — the running app's chrome is gold; other themes keep their own accent. Appearance only: shared controls, composer box, pill badges, and a capped branch list so the file list stays visible.
- **The frame is the goal, not a recolor** — `docs/VISUAL-GOAL.md`. A tab strip, status bar, two-line session rows, and a settings section list use data the app already has. They do not add a file browser, bots page, or wallpaper.
- **Files panel lists names only, under the chat's project folder or the home folder** — `GET /chats/:id/files` resolves the path and refuses anything outside that root, including a symlink. Capped at 300 names. It never reads file contents and never returns a full path. Dragging a tab writes `tabOrder` without changing `updatedAt`, so a drag does not look like a new message. The soft background is a CSS gradient, not a copied picture, and turns off in Settings.
- **The shell follows the light desktop screenshots, not a dark tool** — default theme is light. Sessions and Agents sit together at the top of the left rail. The folder control lives in that rail, and moves to a 28px icon in the top bar when the rail is hidden, so a wrapping label cannot cover the chat. Changes opens in the shared dialog (Escape, focus trap), not a right column. Text size is 13px times a scale (80–125), changed from the status bar or Settings.
- **Superseded (item 5, 2026-11-28): the default theme is now the dark gold `pheme-gold` matching the Hermes webapp reference** (gold `#FFBF00` on navy `#1a1a2e`, built from the stock gold-on-navy skin; server default `pheme-gold-dark`; bare saved values `light`/`dark`/`system` resolve to it). The "light desktop screenshots" line above no longer applies; the right panel becomes a column (item 7), not the shared dialog.
- **Tailwind v4 via `@tailwindcss/vite` 4.3.5 on Pheme's Vite 6.4.6 (item 5)** — proven in a throwaway build first; no Vite upgrade needed (the plugin supports Vite 5-8). Compiled at build time into the one embedded stylesheet, no CDN. Preflight is not imported until components move to utilities (items 6-7), and `tailwind.css` says where to add it. The skin converter (`skin.ts`) runs at build time in `scripts/gen-themes.mjs`, not in the browser. Old `--dt-*` names are mapped onto the Hermes seed chain in `tokens.css`; body is 13px/1.5, chat text scale defaults to 110% (transcript and composer only).
- **The working mark in a chat is one of three, chosen in Settings** — marching grid (default), sphere of light, or sphere of mist. Saved in this browser (`pheme-loader`). A bad or missing save is the grid. Shown while a reply is running, including while text is streaming. Motion stops when the system asks for reduced motion.
- **Goal is an exact match of the Hermes webapp (owner, 2026-11-28)** — replaces "match the frame". Reference shots: `docs/visual/hermes-reference/`.
- **Porting Hermes code is allowed (MIT, upstream commit `5688461d66fadd3ce3d6ed6bccccd958c7370eae`)** — never copy Hermes/Nous names, logos, brand mark, artwork, backgrounds or app icons, or the fonts Collapse, Rules, Mondwest and NeueBit. Every copied file gets the header `// Adapted from hermes-agent (MIT, Copyright (c) 2025 Nous Research), apps/desktop/src/<path> @ 5688461d`.
- **Hybrid port: Tailwind v4 + Hermes token layer + ported `components/ui` primitives + ported chat and shell components rewired onto Pheme's `blocks.ts` and SSE** — no assistant-ui, nanostores or react-query. Also not used: `@nous-research/ui` (it ships the foundry fonts).
- **Stub-or-skip policy** — build only UI the Copilot CLI backend can support. Hermes pages that need a backend Copilot does not have are skipped.
- **Real-Copilot event probe (build-plan item 4) skipped by the owner** — Copilot-dependent UI (reasoning, intent, todos, progress, effort pill) is built from the pinned SDK's type definitions, feature-detected (hidden when the event never arrives), and tested in fake mode only. It has not been seen from a real CLI.
- **Activity events mapped from the pinned SDK types, none confirmed on real Copilot (build-plan item 11)** — the real-run probe (item 4) was skipped, so these come from `@github/copilot-sdk` 1.0.34 `generated/session-events.d.ts` and `rpc.d.ts`. Status: type-defined, **not seen on a real CLI** for any event.
  - `assistant.reasoning_delta` → `reasoning_delta` (streamed, not persisted; `deltaContent`, `reasoningId`)
  - `assistant.reasoning` → `reasoning` (persisted; `content`, `reasoningId`; `ms` measured by Pheme from the first delta, absent when no delta came)
  - `assistant.intent` → `intent` (persisted; `intent`; shown in the working row for the current turn only)
  - `session.todos_changed` → `todos` (persisted; the event is signal-only, so Pheme reads `session.rpc.plan.readSqlTodosWithDependencies()`, an `@experimental` RPC, and keeps rows with a title; the list is shown while any item is unfinished)
  - `tool.execution_progress` → `progress` and `tool.execution_partial_result` → `progress` with `partial: true` (streamed, not persisted; the last line shows under the running tool row)
  - `session.title_changed` → `title` (not persisted; replaces the chat title only while it is still the automatic one)
  - Not mapped: `tool.shell_output` (raw shell chunks; the progress line covers the need for now).
  - Fake mode: `think <text>` emits all of the above; tests in `packages/server/test/activity.test.ts`, `packages/ui/test/thinking.test.tsx` and the fake-mode e2e test in `e2e/smoke.spec.ts`. A missing event hides its piece: no reasoning means no Thinking block, no intent means "Working", no todos means no Todos row, no progress means no line under a tool.
  - Setting "Collapse thinking by default" (`collapseThinking`, default off) removes the live preview only.
