## Q1. Which libraries power the chat, and where does each component live?

### Takeaway
The chat is built on **assistant-ui** (`@assistant-ui/react` 0.14.29 with `@assistant-ui/core` 0.2.23), using an incremental external-store runtime fed by Hermes' own gateway stream. Markdown goes through **Streamdown** (`@assistant-ui/react-streamdown` 0.3.7, `streamdown` 2.7.0, `@streamdown/code`, `@streamdown/math` with KaTeX). Code is highlighted by **Shiki** 4.5 (`react-shiki`). Scroll-follow uses **use-stick-to-bottom** 1.1.6. Motion uses **motion** 12.43 (Framer Motion), the Web Animations API and plain CSS keyframes. The shimmer effect comes from **tw-shimmer**. Icons are Tabler and VS Code Codicons, with a few lucide icons. State lives in nanostores. Every renderer on top of these libraries is custom Hermes code.

### Inferences
- Pheme can reuse most of this as-is if it adopts assistant-ui with an external-store runtime. The Hermes components depend on assistant-ui primitives (`MessagePrimitive`, `ActionBarPrimitive`, `BranchPickerPrimitive`, `ComposerPrimitive`, `ThreadPrimitive.MessageByIndex`, `useAuiState`), so porting them without assistant-ui means rewriting those primitives.
- Most of the complexity is performance work: render budgets, memoized element identity, deferred markdown parsing. A first port can skip much of it and still match visually.

### Gaps
- I did not trace the gateway-to-`ThreadMessage` conversion in detail (`lib/chat-messages/*`, `app/session/hooks/use-message-stream/*`). The part shapes it produces (`tool-call` with `completedAt`, `timestamp`, `interrupted`, `innerToolName`; `reasoning` parts; `metadata.custom.interim|durationS|interrupted|errorSurface`) are inferred from the consumers.

## Q2. Transcript: how are user and assistant messages laid out?

### Takeaway
Hermes uses no avatars and no names. The transcript is one centered column (`max-w-(--composer-width)`, `px-6`). User prompts are right-anchored, full-width rounded-xl "glass" bubbles that stick to the top of the scroller for the whole turn and clamp to about 4 lines with a fade. Assistant replies are unboxed prose, indented 0.75rem, with tool and thinking "scaffolding" lines in a dimmer grey (opacity 0.67) between paragraphs. Each user message and its replies form one "turn pair" group.

## Q3. How are markdown and code blocks rendered (highlighter, copy buttons)?

### Takeaway
Markdown goes through Streamdown's `StreamdownTextPrimitive` in `mode="streaming"` with custom components inside a Tailwind `prose` container. Headings are shrunk to chat scale and `---` renders as blank space. Code fences render as a borderless tinted slab with no header and no language label. Shiki highlights them lazily (github-light-default / github-dark-dimmed) once streaming ends. The block caps at 7.5rem with a bottom fade and a chevron expander, and a copy icon appears top-right on hover.

Inline code is `rounded-[0.25rem] px-[0.1875rem] py-px font-mono text-[0.9em]` with backtick pseudo-content removed. Spacing is `[&>*+*]:mt-(--paragraph-gap)` — [markdown-text.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/assistant-ui/markdown-text.tsx)

## Q4. How does streaming text behave (cursor, fade-in, chunking), and how does scroll-follow work?

### Takeaway
There is no typing cursor and no per-character smoothing. Text is appended as deltas arrive, and markdown parsing is deferred with React `useDeferredValue` while a tail-bounded repair (remend) closes unfinished syntax. New blocks (messages, tool rows, thinking blocks) get a one-time 180ms slide-up of 0.375rem. Scrolling is owned by `use-stick-to-bottom` with **instant** follow (no spring). Scrolling up escapes the follow, and a floating "Scroll to bottom" pill appears that can count new messages below.

### Cited Findings
- No smoothing: "No `smooth` on purpose — same as the assistant answer… a smoothed reasoning stream re-types from the first character on every delta (the flash)… Plain append matches the answer." — [markdown-text.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/assistant-ui/markdown-text.tsx)
- Streaming parse: `StreamdownTextPrimitive mode="streaming" parseIncompleteMarkdown={false} preprocess={preprocessWithTailRepair} parseMarkdownIntoBlocksFn={cached}`. The text is read through `useDeferredValue(useMessagePartText())` so parsing happens in an interruptible render. The source comments say deltas arrive at roughly 30 Hz ("~30×/s") — [markdown-text.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/assistant-ui/markdown-text.tsx); [assistant-message.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/assistant-ui/thread/assistant-message.tsx)
- Enter animation (`useEnterAnimation`): WAAPI `el.animate([{transform:'translateY(0.375rem)'},{transform:'translateY(0)'}], {duration:180, easing:'cubic-bezier(0.16, 1, 0.3, 1)', fill:'backwards'})`. It is transform-only (no opacity), plays once per key (keys are remembered in a 2048-entry LRU), only for elements that mount while their message is running, and is skipped under reduced motion. It is used for assistant messages, tool entries, tool runs and thinking blocks — [lib/use-enter-animation.ts](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/lib/use-enter-animation.ts)

The comment: "Snap instantly, not spring — a spring can't tell live-token growth from a session-switch bulk relayout". Snaps are suppressed while the user has a text selection in the transcript. CSS sets `overflow-anchor: none` while following and `auto` once escaped or editing — [list.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/assistant-ui/thread/list.tsx); [styles.css](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/styles.css)

It un-dims after a scroll stall — [composer/index.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/app/chat/composer/index.tsx); [styles.css](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/styles.css)

## Q11. What motion and micro-interactions does the chat use (durations, easings, libraries)?

### Takeaway
Motion is short and functional. The house curve is `cubic-bezier(0.16,1,0.3,1)` (or `0.22,1,0.36,1`) at 180–240ms. Hover paints instantly and only the return eases. Scaffolding sits at 0.67 opacity and lifts to 1 on hover. Continuous animations are avoided or paused when the window is hidden. The libraries are `motion/react` (height and stack animations), WAAPI (enter slides, status pulse) and CSS keyframes (ticker, jump button, code-card glow, reactions, shimmer via `tw-shimmer`).

### Cited Findings
- Rules: "Quick, functional transitions (~100ms on controls)"; "Hover paints instantly; only the return eases… `transition-colors duration-100 hover:transition-none`"; "Motion follows state; it never delays state"; respect `prefers-reduced-motion` — [DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/DESIGN.md)

## Q12. Which Hermes chat features depend on backend capabilities a GitHub Copilot CLI backend may not provide?

### Takeaway
Most visuals work on any streaming backend that exposes text deltas, tool start and complete events, and permission requests. The features that need specific backend support are: reasoning text and effort levels, branching and checkpoint restore, steer and interrupt-redirect, the queue, delegated sub-agent sessions, structured error surfaces, inline diffs in tool results, MCP progress, "always allow" patterns, compaction status and drafting-tool hints.

- These are likely fine on a Copilot CLI backend: streaming text, tool rows and run summaries (with a tool-name mapping), approvals (once and session), stop, queue (held client-side and sent when idle, as Hermes' queue already does on the client), copy, retry (resend the last prompt), turn duration, and changed-files (if Pheme computes changes from git).

- These are not applicable without Hermes infrastructure: compaction hints, local-model load bars, MCP progress percentages, inter-agent message notices, voice, and reactions (reactions would be client-only).

### Gaps
