# Pheme UI audit and Hermes port feasibility (state as of 2026-11-28)

Scope: Pheme's own UI (`packages/ui`), how it talks to `packages/server`, and what porting the Hermes desktop UI (and web dashboard) would involve. Hermes's visual system, chat flow and dashboard pages in detail are covered by other researchers.

Sources used:
- Pheme repo, read-only, at `/home/user/pheme`. Local paths are given as sources (`pheme:<path>`).
- Hermes clone, shallow, at commit `5688461d66fadd3ce3d6ed6bccccd958c7370eae` (2026-11-27). Abbreviation: `HERMES` = `https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae`.
- The `@github/copilot-sdk@1.0.34` npm tarball (the version Pheme pins). Its type files were read; none of its code was run.
- The `@nous-research/ui@0.19.1` npm tarball, used to check what the font files are.

## 1. Pheme UI stack today

### Takeaway
Pheme's UI is a small app: about 9.8k lines across UI source and tests, about 40 source files. It uses React 19 + Vite 6 with hand-written plain CSS (3 files, about 630 lines) on `--dt-*` theme tokens, local `useState`/hooks for state, a custom hash router, react-markdown + highlight.js, vitest + Testing Library (38 test files), and one Playwright smoke spec. It ships as a single `dist/pheme.mjs` with the UI base64-embedded. There is no Tailwind, no component library, no icon set (emoji/Unicode glyphs serve as icons), almost no motion (4 `transition` rules), and system fonts only.

### Cited Findings
- **Framework/deps.** The UI package depends only on `react`/`react-dom` ^19, `vite` ^6, `@vitejs/plugin-react` ^4, `react-markdown` ^10, `remark-gfm` ^4, `rehype-highlight` ^7 and `highlight.js` ^11. — [pheme:packages/ui/package.json](/home/user/pheme/packages/ui/package.json)
- **Root tooling.** Node >=22.12, npm workspaces (`packages/*`), TypeScript ^5.6, vitest ^3, jsdom, Testing Library (react, user-event, jest-dom), Playwright ^1.65, esbuild ^0.25, eslint 9. Scripts: `typecheck`, `lint`, `test`, `build` (`scripts/build.mjs`), `smoke`, `stress`, `e2e`, `verify`. — [pheme:package.json](/home/user/pheme/package.json)
- **Styling.** Plain CSS in `styles.css` (314 lines), `app.css` (258) and `markdown.css` (54). It is written as dense one-line rules: `.shell`, `.sidebar`, `.chat-row`, `.tool-row`, `.btn.primary` and so on. The body font is `calc(13px * var(--chat-text-scale, 1))/1.45 var(--dt-font-sans)`, and the defaults are `--dt-font-sans: system-ui, sans-serif` and `--radius: 0.625rem`. The header comment says the principles follow Hermes `DESIGN.md` ("flat not boxed, tokens not literals"). — [pheme:packages/ui/src/styles.css](/home/user/pheme/packages/ui/src/styles.css)
- **Tokens/themes.** `themes/generated.ts` (424 lines) is generated by `scripts/gen-themes.mjs` from the Hermes preset table: 11 themes, with nous renamed to pheme and nous-alt to pheme-alt. Only about 24 distinct `--dt-*` tokens are used across Pheme's themes and CSS, and there are no `--ui-*` tokens. — [pheme:docs/DECISIONS.md line 34](/home/user/pheme/docs/DECISIONS.md); grep of `pheme:packages/ui/src/themes/*.ts` and `*.css`
- **Fonts.** Per-theme web fonts are deliberately not loaded ("the work laptop may block them, so every theme uses system font stacks"). — [pheme:docs/DECISIONS.md line 34](/home/user/pheme/docs/DECISIONS.md)
- **Theme boot.** `index.html` has an inline script that reads `localStorage["pheme-theme-boot"]` to paint `--dt-background`/`--dt-foreground` and the `dark` class before React mounts. — [pheme:packages/ui/index.html](/home/user/pheme/packages/ui/index.html)
- **Routing.** The custom hash router supports `#/chat/<id>`, `#/skills/<name>`, `#/memory`, `#/agents`, `#/prompts`, `#/jobs` and `#/settings`. Unknown hashes fall back to a new chat. — [pheme:packages/ui/src/router.ts](/home/user/pheme/packages/ui/src/router.ts)
- **State.** There is no store library. The app uses hooks (`useChat.ts`, `useGit.ts`, `connection.ts`), with localStorage for drafts, keybindings, loader choice and the access key. — [pheme:packages/ui/src/](/home/user/pheme/packages/ui/src/); [pheme:docs/DECISIONS.md lines 55, 66, 73](/home/user/pheme/docs/DECISIONS.md)
- **Transport.** REST is `fetch("/api"+path)` with an `x-pheme-token` header. Streaming is one `EventSource` per open chat at `/api/chats/:id/events?after=<seq>&token=…`, which resumes by sequence number. `/api/state` is polled for usage/settings and offline detection. — [pheme:packages/ui/src/api.ts](/home/user/pheme/packages/ui/src/api.ts), [useChat.ts](/home/user/pheme/packages/ui/src/useChat.ts), [connection.ts](/home/user/pheme/packages/ui/src/connection.ts)
- **Markdown.** react-markdown + remark-gfm + highlight.js (20 languages), lazy-loaded as its own chunk. Main JS went from 735 kB to 327 kB after that split, and the earlier total was about 725 kB of JS ("accepted"). — [pheme:docs/DECISIONS.md lines 45, 52](/home/user/pheme/docs/DECISIONS.md)
- **Transcript model.** `blocks.ts` turns the event log into blocks: `user`, `assistant`, `tools` (consecutive tool calls grouped, results merged), `approval`, `agent` and `notice`. Groups of more than 3 tools collapse. Long chats render only the last 400 events. — [pheme:packages/ui/src/blocks.ts](/home/user/pheme/packages/ui/src/blocks.ts), [Transcript.tsx](/home/user/pheme/packages/ui/src/Transcript.tsx)
- **Tests.**
  - About 38 UI test files in `packages/ui/test`. 23 of the `.tsx` tests query by role/text/label and 10 use `querySelector`/class checks.
  - The Playwright smoke spec selects heavily on CSS classes: `.bubble.user`, `.assistant`, `.sidebar-wrap`, `.menu-btn`, `.shell.drawer-open`, `.panel:not([hidden]) h3`, `.change-row`, `.diff .dl.add`, `.commit-done`, `.branch-pill` and `.stash-list li`.
  - v0.3.0 verification reported 626 unit tests and 13 browser tests.
  - Sources: [pheme:e2e/smoke.spec.ts](/home/user/pheme/e2e/smoke.spec.ts), [pheme:PROGRESS.md "v0.3.0"](/home/user/pheme/PROGRESS.md), grep of `pheme:packages/ui/test`
- **Single-file delivery.** `scripts/build.mjs` reads every file in the UI `dist`, base64-encodes it into an `assets` map, and injects it through esbuild `define: { __PHEME_ASSETS__ }`. It also writes `THIRD_PARTY_LICENSES.txt` for the UI dependency tree. — [pheme:scripts/build.mjs](/home/user/pheme/scripts/build.mjs); [pheme:docs/DECISIONS.md lines 9, 46](/home/user/pheme/docs/DECISIONS.md)
- **No npm install on the laptop.** Delivery is `dist/pheme.mjs` plus `start-pheme.cmd`, with nothing to install on the work laptop. — [pheme:docs/PLAN.md §1](/home/user/pheme/docs/PLAN.md)
- **No service worker.** The PWA has a manifest and icons and no service worker "on purpose (nothing can serve a stale UI or cache chats)". — [pheme:docs/DECISIONS.md line 66](/home/user/pheme/docs/DECISIONS.md)
- **Icons.** Emoji and Unicode glyphs act as icons: 📁 (ProjectBar), 📎 and 🖼 (Composer/AttachmentView), 📋 (prompt picker), ✕ (close), ⎇ (branch), ⚠, and ✓/✗/● (PR checks). There is no icon library. — grep of `pheme:packages/ui/src/*.tsx`
- **Motion.** Only 4 `transition` declarations exist: the drawer slide (0.2s), message-actions opacity (0.12s), plus `spin`/`pulse` keyframes and a reduced-motion kill switch. There are three "working" loaders (grid, sphere of light, sphere of mist). — [pheme:packages/ui/src/app.css](/home/user/pheme/packages/ui/src/app.css), [styles.css](/home/user/pheme/packages/ui/src/styles.css); [pheme:docs/DECISIONS.md line 73](/home/user/pheme/docs/DECISIONS.md)

### Inferences
- The Pheme codebase is small enough (about 40 files) that a full UI rewrite is affordable. Server API and protocol stability are the real assets to protect.
- Because `blocks.ts` already normalises events into turn parts, it is the natural seam for an adapter to Hermes/assistant-ui-style message parts.
- The e2e suite's reliance on CSS class names means any restyle that renames classes breaks e2e unless stable `data-testid`/role selectors are introduced first. That is cheap to do before the port.
- Visible defects in the current screenshots:
  - The "fake" engine pill renders as a tall blue blob in the top-right of the light shell.
  - Emoji icons (📁, 📋) render inconsistently.
  - The commit-message textarea in the Changes panel is clipped.
  - The branch "Filter…" input is unstyled.
  - Source: `pheme:docs/visual/shell.png`, `changes-shell.png`, `settings-shell.png` (viewed).

### Gaps
- Current built size of `dist/pheme.mjs` was not measured (no `dist/` in the checkout, and building was out of scope for a read-only audit). Only the DECISIONS figures above are available.

## 3. Stack gap vs Hermes desktop and porting options

### Takeaway
Hermes desktop is roughly 50x larger than Pheme:
- about 474k lines of non-test TS/TSX in 2,137 files, against Pheme's about 9.8k;
- built on Tailwind v4, shadcn-style components on `radix-ui`, `@assistant-ui/react` with a custom external-store runtime, `nanostores` (about 340 imports), `@tanstack/react-query` (159), `motion`, Tabler icons and codicons, and `streamdown`/`shiki` for markdown.

Its chat components are wired to Hermes stores (`$gateway`, session-view, i18n, haptics, keybinds). Wholesale adoption (a) is therefore really a re-platform with a large shim layer. The best risk/fidelity trade-off is a **hybrid (c)**:
- adopt Tailwind v4 and Hermes's token layer (`@theme inline` + `--dt-*`/`--ui-*`) and Hermes's `components/ui` primitives nearly verbatim;
- port selected chat/composer/tool/approval components file by file, replacing store hooks with thin adapters over Pheme's existing API/SSE;
- skip assistant-ui unless the message-part model is needed.

### Inferences (effort, risk, bundle, tests)

**(a) Adopt Tailwind + Hermes components wholesale (including assistant-ui runtime, nanostores, react-query).**
- Fidelity: highest. Pixel-identical is possible for ported surfaces.
- Effort: very high. You must either re-implement Hermes's gateway/session-view/prompts stores as a Pheme adapter, or copy them and stub the hundreds of feature flags, plugins, i18n keys and desktop-only hooks. The Hermes toolchain (Vite 8, TS 6, React compiler, Node 26, pnpm) is ahead of Pheme's (Vite 6, TS 5.6, Node 22.12, npm), so upgrading Pheme's toolchain or back-porting code is required.
- Risk: high. Upstream internals move fast: the runtime imports `@assistant-ui/core/internal`, and dependencies are exact-pinned. Pheme would inherit a large surface it cannot fully test with a fake engine.
- Bundle: +250–450 kB gzip-equivalent JS plausible. That is fine for a local single file, but it slows the base64 `pheme.mjs` build and startup modestly.
- Tests: nearly all 38 UI test files and the e2e spec would need rewriting.

**(b) Port tokens/CSS only and rewrite components by hand in plain CSS.**
- Fidelity: medium. This is the current approach, and it already shows drift (blob pill, clipped textarea, emoji icons).
- Effort: medium, but endless. Every Hermes class string has to be translated by hand.
- Risk: low technically, high for "exact match".
- Bundle: approximately zero change.
- Tests: mostly kept.

**(c) Hybrid (recommended).**
1. Add Tailwind v4 via `@tailwindcss/vite`. Port Hermes `styles.css` token and `@theme` sections plus the base layer, and extend `gen-themes.mjs` to emit the full `--dt-*` and `--ui-*` set.
2. Copy `components/ui` primitives (button, dialog, dropdown-menu, tooltip, command, select, switch, tabs, scroll-area, kbd, glyph-spinner, card-stack, diff-count, file-type-icon) with `radix-ui`, `cva`, `clsx`, `tailwind-merge`, Tabler icons via a trimmed `lib/icons.ts`, and `motion`.
3. Port visual components one by one: session-tile, sidebar rows, composer shell, tool fallback/run-ticker, approval card, status bar, settings layout. Replace `$gateway`, assistant-ui and nanostores reads with props or small Pheme hooks fed by `blocks.ts`.
4. Keep react-markdown, or optionally move to streamdown + shiki for exact code-block look.

## 4. Engine/event mapping and Copilot-CLI limits

### Takeaway
Pheme's wire protocol has 13 `ChatEvent` types. Its engine maps only a subset of the Copilot SDK's events:
- message deltas and messages;
- tool start/complete;
- `subagent.*`;
- `session.error`;
- `session.usage_info`;
- `session.idle`;
- permission requests via a callback.

The SDK pinned by Pheme (1.0.34) also exposes reasoning and reasoning deltas, intent, per-call usage/cost, tool progress and partial results, shell output, todos, title changes, compaction, elicitation, and per-model `supportedReasoningEfforts`/`reasoningEffort`. So a **reasoning-effort pill, a reasoning ("Thinking") disclosure, an intent/progress ticker, a todo list and live shell output are backable** with server work, contrary to Pheme's earlier "no reasoning menu" stance. Providers/billing, bots/messaging gateways, webhooks, profiles, pets/starmap/HUD, voice, local models, MCP/plugin/connector managers, the browser/preview pane and the built-in terminal are not backable, or are out of scope.

### Cited Findings
- **Pheme protocol.** `ChatEvent` = `user` (with attachments), `delta`, `message`, `tool_start {id,name,args}`, `tool_end {id,name,ok,result}`, `approval_request {id,kind,title,detail}`, `approval_resolved {id,decision: once|chat|deny}`, `notice {kind: skill|memory|info}`, `agent_update {run}`, `turn_start`, `idle`, `usage {used,limit}`, `error`. Events are numbered (`seq`, `ts`). — [pheme:packages/server/src/protocol.ts](/home/user/pheme/packages/server/src/protocol.ts)
- **Engine mapping.**
  - Mapped SDK events: `assistant.message_delta`, `assistant.message`, `tool.execution_start`, `tool.execution_complete`, `subagent.started/completed/failed`, `session.error`, `session.usage_info` (remembered and emitted once per turn), and `session.idle`.
  - Permission kinds: `read` is auto-approved, and shell/write/url/mcp become an approval card ("Run shell command", "Edit file", "Fetch URL", "Use MCP tool").

- **SDK 1.0.34 event types (from its generated `session-events.d.ts`).** These include `assistant.reasoning`, `assistant.reasoning_delta`, `assistant.intent`, `assistant.usage`, `assistant.turn_start/turn_end`, `assistant.tool_call_delta`, `tool.execution_progress`, `tool.execution_partial_result`, `tool.shell_output`, `session.todos_changed`, `session.title_changed`, `session.compaction_start/complete`, `session.quota_observation`, `session.model_change`, `session.mode_changed`, `session.plan_changed`, `elicitation.requested/completed`, `permission.requested/completed`, `skill.invoked` and `subagent.selected`, among about 130 types. — [npm @github/copilot-sdk 1.0.34 tarball](https://registry.npmjs.org/@github/copilot-sdk/-/copilot-sdk-1.0.34.tgz) (`dist/generated/session-events.d.ts`)

## 5. Fonts and assets: can Hermes fonts be bundled into pheme.mjs?

### Takeaway
Hermes desktop's UI typography is **system fonts** (Segoe UI / SF Pro / system-ui). The only bundled face that matters for the chat UI is **JetBrains Mono** (3 woff2 files, about 283 KB, under SIL OFL 1.1, which allows bundling). It can be embedded in pheme.mjs (+about 377 KB base64, or about 123 KB for Regular only). It also fixes the blocked-web-fonts problem, because it is served by Pheme itself. The Nous brand display faces shipped in `@nous-research/ui` (Collapse, Rules Compressed/Expanded, Mondwest, NeueBit) are commercial foundry fonts and must **not** be copied, even though that npm package says "MIT". The web dashboard's Oswald and Mona Sans are OFL and could be bundled if the dashboard look is wanted.

### Cited Findings
- **Hermes desktop font stacks.**
  - Default typography is `SYSTEM_SANS` = `"Segoe WPC", "Segoe UI", -apple-system, BlinkMacSystemFont, "SF Pro Text", "SF Pro Display", system-ui, sans-serif` plus emoji.
  - `SYSTEM_MONO` begins with the bundled `"JetBrains Mono"`, then `"Cascadia Code"` and others.
  - Some themes add Google Fonts URLs (Courier Prime, JetBrains Mono, IBM Plex Mono).
  - Source: [HERMES src/themes/presets.ts](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/themes/presets.ts)
- **Hermes base text metrics.** `html { font-size: var(--dt-base-size, 0.875rem) }` (theme sets `--dt-base-size: 1rem`), `body { font-size: 0.8125rem; line-height: var(--dt-line-height, 1.55); -webkit-font-smoothing: antialiased; user-select: none }`, `--dt-line-height: 1.5`, `--radius: 0.75rem`. — [HERMES src/styles.css lines ~475–495, 797–822](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/styles.css)
- **Pheme for comparison.** `13px/1.45`, `--radius: 0.625rem`, no antialiasing rule. — [pheme:packages/ui/src/styles.css](/home/user/pheme/packages/ui/src/styles.css)
- **Hermes size classes.** The most frequent are `text-xs` (488 uses), `text-[0.6875rem]` (139), `text-sm` (126), `text-[0.625rem]` (86) and `text-[0.7rem]` (77). — grep of `HERMES apps/desktop/src/**/*.tsx`
- **Bundled faces.** Hermes ships `src/fonts/JetBrainsMono-{Regular,Bold,Italic}.woff2` (92,380 + 94,628 + 96,428 bytes). Its CSS comment calls it "Apache-2.0". Collapse Bold is loaded from `@nous-research/ui/fonts/Collapse-Bold.woff2` and used only for `.wordmark` (the empty-chat "HERMES" display lettering). — [HERMES src/styles.css lines 95–125, 2015–2025](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/styles.css); `ls -la HERMES/apps/desktop/src/fonts`
- **JetBrains Mono licence.** It is under SIL Open Font License 1.1, "Copyright 2020 The JetBrains Mono Project Authors". It may be bundled or embedded and sold with software if each copy includes the copyright notice and licence. It cannot be sold by itself, and reserved font names can't be used by modified versions. Hermes's "Apache-2.0" comment is therefore outdated. — [JetBrains Mono OFL.txt](https://github.com/JetBrains/JetBrainsMono/blob/master/OFL.txt)
- **What `@nous-research/ui@0.19.1` contains.** The package says `"license": "MIT"` in package.json but ships no LICENSE file. It includes `src/fonts/` with Collapse (Thin/Light/Regular/Bold + italics, 8 files, about 60 KB each), RulesCompressed-{Regular,Medium}, RulesExpanded-{Regular,Bold}, Mondwest-Regular and Neuebit-Bold. — [npm @nous-research/ui 0.19.1](https://registry.npmjs.org/@nous-research/ui/-/ui-0.19.1.tgz) (inspected tarball)
- **Collapse.** A paid Blaze Type typeface by Axel Keussel Andre (2024): 8 styles (Thin, Light, Regular, Bold, each with italic), sold with Purchase/trial and Font Pack subscription. — [Blaze Type: Collapse](https://blazetype.eu/typefaces/collapse)
- **Rules.** Also a Blaze Type family (89 styles). — [MyFonts: Rules by Blaze Type](https://www.myfonts.com/collections/rules-font-blaze-type)
- **Mondwest (and NeueBit).** Pangram Pangram faces. Pangram Pangram's general terms limit trial/free files to personal non-commercial use, and I found no source confirming a free commercial licence for Mondwest. — [Pangram Pangram FAQ](https://pangrampangram.com/faq), [befonts listing](https://befonts.com/designer/pangram-pangram)
- **Web dashboard fonts.** It loads Oswald (headings) and Mona Sans (body) from Google Fonts with system fallback, and serves Mondwest and JetBrains Mono from `public/`. It deliberately does not import the DS `fonts.css` "would bundle the Collapse and Rules faces". — [HERMES web/src/index.css](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/web/src/index.css)
- **Mona Sans licence.** SIL OFL 1.1 (GitHub). — [github/mona-sans](https://github.com/github/mona-sans)
- **Oswald licence.** SIL OFL 1.1, "Copyright 2016 The Oswald Project Authors". — [google/fonts ofl/oswald/OFL.txt](https://raw.githubusercontent.com/google/fonts/main/ofl/oswald/OFL.txt)
- **Base64 mechanism.** Pheme's build already base64-embeds every file in the UI `dist`, so woff2 files emitted by Vite would be served from memory with no external request. A font MIME type may need adding to the `TYPES` map. — [pheme:scripts/build.mjs](/home/user/pheme/scripts/build.mjs)

### Inferences
- **The "fix typography" work is mostly metrics, not new faces:** adopt Hermes's root and base sizes, line-height 1.5–1.55, antialiasing, Tailwind's text scale and weights, and letter-spacing on small caps. Bundle JetBrains Mono for code, diffs and tool rows. Keep the system sans stack, which is exactly what Hermes uses, so the work laptop's font blocking is a non-issue.
- **Size.** About 283 KB raw for 3 JetBrains Mono files becomes about 377 KB once base64-encoded inside pheme.mjs. Regular only would be about 92 KB raw / 123 KB base64. Subsetting to Latin would shrink it further.
- **Don't-copy list:** the empty-chat wordmark treatment needs a replacement face, or system sans in caps. Do not copy Collapse, Rules, Mondwest or NeueBit, even via the MIT-labelled npm package. A font's licence is set by its foundry, and the package's MIT label does not show that Nous may relicense Blaze Type or Pangram Pangram fonts.
- **Licence notice.** If OFL fonts are bundled, add the OFL text and copyright lines to `THIRD_PARTY_NOTICES.md` and `THIRD_PARTY_LICENSES.txt`. Do not rename modified versions to a reserved name.

### Gaps
- I could not reach Blaze Type's or Pangram Pangram's actual EULA pages. The conclusion "commercial, do not copy" rests on product pages and foundry FAQs, which is enough to exclude them.
- I have no Hermes statement on how Nous licensed these fonts.
