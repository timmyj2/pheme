# Rebuild Pheme's UI on Hermes's own foundations

Pheme should adopt Hermes's actual front-end stack and port its code file by file. It should not keep hand-copying Hermes's look in plain CSS. Pheme's UI is small, about 9.8k lines in about 40 files, with plain CSS, system fonts, emoji icons and four CSS transitions ([DECISIONS.md](file:///home/user/pheme/docs/DECISIONS.md), [package.json](file:///home/user/pheme/packages/ui/package.json)). Hermes desktop is about 474k lines on Tailwind v4, shadcn-style primitives, assistant-ui and nanostores ([Hermes package.json](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/package.json)). Taking all of that is a re-platform. Keeping plain CSS is what produced the "not true Hermes" drift. The best path is a **hybrid**. Add Tailwind v4 and Hermes's token layer. Copy Hermes's `components/ui` primitives near-verbatim. Port the chat, composer, tool, approval and shell components by file. Rewrite only their state wiring so it reads Pheme's existing `blocks.ts` and SSE stream. Skip assistant-ui. The MIT licence allows all of this, but names, logos, artwork and the brand fonts must stay out. The Copilot SDK can back reasoning, intent, progress and todo UI, but only a real-Copilot check can confirm that CLI 1.0.112 sends those events. The plan at the end starts with the docs that forbid copying, then adds test selectors, then restyles.

## Pheme feels generic because the frame matches and the details do not

Pheme already copies Hermes's frame. It has a tab strip with an underline, accent small-caps labels, two-line session rows, a status bar and a rounded composer ([PARITY.md](file:///home/user/pheme/docs/PARITY.md)). The gap is in the details that make Hermes feel like Hermes. These details are numbers.

Type is the clearest gap. Hermes sets `body` to 13px with line-height 1.5, antialiased, on a 16px root ([Hermes styles.css](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/styles.css)). It then applies a **110% default chat text multiplier** to the transcript and composer ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/DESIGN.md)). Transcript text is therefore about 14.3px. Tool rows are 11px at the same scale, captions 12px, and section labels about 10.2px, uppercase, 0.16em tracking, in the theme's primary colour ([sidebar-label.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/app/shell/sidebar-label.tsx)). Pheme's body is `13px × scale / 1.45` with no antialiasing rule ([styles.css](file:///home/user/pheme/packages/ui/src/styles.css)). If its scale default is 100%, Pheme's chat text is about 9% smaller than Hermes's and looser in line height. That alone reads as "dated". The font family is not the problem. Hermes uses **system fonts** for the UI: Segoe UI, SF Pro, system-ui ([presets.ts](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/themes/presets.ts)). The only bundled face is JetBrains Mono for code, in three woff2 files of about 92 KB each ([styles.css](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/styles.css)). Pheme's rule against web fonts, made for a work laptop that may block them, stays valid. Pheme should embed JetBrains Mono in `pheme.mjs`, which adds about 377 KB base64 for all three files or about 123 KB for Regular only. Pheme's own build already base64-embeds every file in the UI `dist` ([build.mjs](file:///home/user/pheme/scripts/build.mjs)), so the font is served by Pheme and cannot be blocked.

Motion is the second gap. Hermes has a short, strict motion language. Controls fade over about 100ms. Hover paints instantly and only the return eases (`transition-colors duration-100 hover:transition-none`). New blocks slide up 0.375rem over 180ms on `cubic-bezier(0.16,1,0.3,1)`, using transform only. Tool and approval heights animate over 0.22s. Scaffolding sits at 0.67 opacity and lifts to 1 on hover. A blanket reduced-motion rule kills it all ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/DESIGN.md), [use-enter-animation.ts](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/lib/use-enter-animation.ts)). Pheme has four `transition` rules and two keyframes, plus three "working" loaders ([app.css](file:///home/user/pheme/packages/ui/src/app.css)). The working signal in Hermes is quiet. It is a 12px dithered square that pulses 1 to 0.5 to 1 over 400ms every 5s, plus a tiny timer ([status-pulse.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/ui/status-pulse.tsx)). Pheme's sphere loaders do not match it.

Icons and density are the third gap. Pheme uses emoji and Unicode glyphs such as 📁, 📎 and ⎇, which render differently on each OS. Hermes uses Codicons for chrome and Tabler for components, and its DESIGN.md says "Do not introduce a third icon set" ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/DESIGN.md)). Hermes also packs rows tightly: 28px nav rows, 26px session rows with a 1px gap, a 28px tab strip, a 20px status bar and 24px titlebar icon buttons. Radii are tiny because `--radius-scalar` is pinned at 0.2, so `rounded-md` is 2px ([styles.css](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/styles.css)). Pheme's `--radius` is 0.625rem, so it looks rounder and softer. The visible defects in Pheme's own screenshots (a tall blue "fake engine" pill, a clipped commit textarea, an unstyled branch filter) come from hand-written one-line CSS rules.

## A hybrid port beats both a full re-platform and more hand-copying

Three options were weighed. Option (a) takes everything: Tailwind, assistant-ui, nanostores and react-query. Fidelity would be highest, but Hermes's chat components are wired into its stores. For example, `tool/approval.tsx` imports assistant-ui state, nanostores, `motion`, the session view, i18n, haptics and `$gateway` ([approval.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/assistant-ui/tool/approval.tsx)). Its runtime imports `@assistant-ui/core/internal`, and its toolchain (Vite 8, TypeScript 6, Node 26, pnpm only) is ahead of Pheme's (Vite 6, TypeScript 5.6, Node 22.12, npm) ([package.json](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/package.json)). Option (b) keeps plain CSS and tokens only. That is the current approach, and it is where the drift came from. Option (c), the hybrid, is the recommendation. Estimated effort is medium to high and staged, risk is moderate, and bundle growth is estimated at +100 to 200 kB gzip. That estimate comes from bundlephobia full-package sizes and has not been measured on a real build.

The hybrid has four moves. First, add Tailwind v4 through `@tailwindcss/vite`. Port Hermes's `@theme inline` mapping, its `:root` token chain (`--theme-*` seeds, then `--ui-*` derived with `color-mix`, then `--dt-*`, then Tailwind `--color-*`), the base layer, `row-hover` and the shadow and stroke tokens. Extend `scripts/gen-themes.mjs` so it writes the full token set. Pheme uses only about 24 `--dt-*` tokens today, against about 39 `--dt-*` and 55 `--ui-*` in Hermes. Second, copy the `components/ui` primitives: button, control, menu, dialog, tooltip, kbd, pane-tab, glyph-spinner, card-stack, diff-count and codicon. These need `radix-ui`, `class-variance-authority`, `clsx`, `tailwind-merge`, `motion`, and a trimmed `lib/icons.ts`. Third, port the visual components one at a time and replace store reads with props and small Pheme hooks. Fourth, leave assistant-ui out. Its message-part model (reasoning, tool-call, text) is easy to rebuild on top of `blocks.ts`, which already groups events into user, assistant, tools, approval, agent and notice blocks ([blocks.ts](file:///home/user/pheme/packages/ui/src/blocks.ts)). The cost is that Hermes components using `MessagePrimitive`, `ActionBarPrimitive` or `useAuiState` cannot be copied unchanged. Their markup and class strings are ported, and their data hooks are rewritten.

Two toolchain points are inferred and not verified. Tailwind v4's Vite plugin should run on Vite 6. Hermes code written for TypeScript 6 and the React Compiler may need small edits. The first plan step to touch Tailwind should prove both with a throwaway build.

The two "Hermes UIs" are not one look, and Pheme must pick. The web dashboard in `web/` is a separate app with a "brand terminal" style. It has a 256px sidebar, uppercase tracked nav, Oswald and Mona Sans type, a 15px base and a teal default theme ([web/src/index.css](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/web/src/index.css), [web/src/App.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/web/src/App.tsx)). Its Chat page is a real terminal in xterm.js over a PTY. The desktop renderer is the strategic browser UI. Hermes also compiles it as the "Webapp" served on port 9120, and the Desktop docs say that is "not the Web Dashboard" ([desktop.md](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/website/docs/user-guide/desktop.md)). The two share only palette hexes and a protocol package ([theme-presets.ts](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/shared/src/theme-presets.ts)). The recommendation is to **match the desktop renderer for the frame, chat and settings, and borrow page patterns from the dashboard**. Those patterns are the page-header context with title, badge and actions, the Sessions filter and search, the Cron schedule builder, and the Config section list with counts. Do not port the dashboard's uppercase nav, fonts or teal skin. An "exact match" of both at once is impossible, because they differ.

## Licence rules are clear, but three repo docs still say the opposite

Hermes is MIT, "Copyright (c) 2025 Nous Research", and Pheme's `THIRD_PARTY_NOTICES.md` already carries that full notice ([LICENSE](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/LICENSE), [notices](file:///home/user/pheme/THIRD_PARTY_NOTICES.md)). `docs/PLAN.md` already records IT approval to copy selected Hermes UI pieces under MIT. Two docs contradict the new decision. `docs/VISUAL-GOAL.md` says "Do not copy its code, assets, logo, or name". `docs/DECISIONS.md` line 22 says the UI is "new code in Hermes's design vocabulary, not a file copy". Both must be rewritten first, or later agents will refuse to copy code. `PARITY.md`'s "Does not match, and why" list and `NEXT.md`'s "Still not a spitting image" line need the same update ([VISUAL-GOAL.md](file:///home/user/pheme/docs/VISUAL-GOAL.md), [PARITY.md](file:///home/user/pheme/docs/PARITY.md)).

What may be copied is code: components, styles, tokens, hooks and layout. What must not be copied is identity. That includes the `nous-girl` brand mark, the `hermes*` sprites and frames, the `filler-bg0.jpg` backdrop, `catalog-wing*.svg`, tier art, app icons, and strings such as "Hermes", "Hermes Agent", "Nous Research" and Nous Portal links ([brand-mark.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/brand-mark.tsx), [public/](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/public)). Pheme's theme generator already renames `nous` to `pheme` and `nous-alt` to `pheme-alt`. It should also drop the `.arc-nous` hero colours and the empty-chat `Wordmark`, which uses the Collapse display font.

Fonts need care. `@nous-research/ui` says `"license": "MIT"` on npm, but it ships Collapse, Rules, Mondwest and NeueBit, which are foundry fonts. Collapse is sold by Blaze Type ([Blaze Type](https://blazetype.eu/typefaces/collapse)). An MIT tag on a package does not let Nous relicense a third party's typeface, so none of these may be copied. JetBrains Mono is safe, but Hermes's CSS comment calls it "Apache-2.0" while the upstream project uses SIL OFL 1.1 ([OFL.txt](https://github.com/JetBrains/JetBrainsMono/blob/master/OFL.txt)). Pheme should ship the OFL text, because it must match the files it ships. Codicons are probably MIT code with CC-BY-4.0 icons. That is unverified and needs a LICENSE check before shipping.

Provenance should be tracked. Pin the upstream commit (`5688461d`, 2026-11-27) in `THIRD_PARTY_NOTICES.md`. Put a one-line "Adapted from hermes-agent apps/desktop/src/<path>" header in each copied file. That is not required by MIT, but it makes later re-syncs possible.

## The chat flow is the clunky part, and most of its fixes are layout and wording

The owner's complaint is the chat and agent flow. Five Hermes behaviours explain most of the difference.

The transcript is one centred column (`max-w-(--composer-width)`, `px-6`) with no avatars and no names. User prompts are full-width rounded `xl` bubbles. They are **sticky** at the top of the scroller for the whole turn and clamp to four lines with a fade. Assistant text is unboxed, indented 0.75rem. Tool and thinking lines share that left edge ([list.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/assistant-ui/thread/list.tsx), [assistant-message.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/assistant-ui/thread/assistant-message.tsx)). Scroll-follow uses `use-stick-to-bottom` with `initial: 'instant'` and `resize: 'instant'`, with no spring. A floating "Scroll to bottom" pill appears when the user scrolls up, and it reads "Approval needed" when an approval is pending ([scroll-to-bottom-button.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/app/chat/scroll-to-bottom-button.tsx)). Streaming text is plain append with no cursor and no smoothing. Markdown parsing is deferred with `useDeferredValue`.

Tools are one dim 11px row each. A running tool shows a braille "breathe" spinner, and success shows no check. The title is a verb phrase such as "Ran command" or "Running command". Only the verb shimmers while pending. A live timer, diff counts (`+N` green, `−N` red) and a duration follow it. Runs of two or more calls fold into one summary line such as "Explored 3 files, ran 5 commands". While live, a one-line ticker reel slides each new call up over 240ms. Expanded rows get a hairline border. They show a `$ command` strip with an `exit N` chip, stdout and stderr in `max-h-20` mono blocks, and diffs with `border-l-2` tinted lines. File edits, delegations and questions are "cards" that break runs ([fallback.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/assistant-ui/tool/fallback.tsx), [run-summary.ts](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/assistant-ui/tool/run-summary.ts)). Pheme collapses groups only when there are more than three tools, with no summary wording, ticker or timer ([blocks.ts](file:///home/user/pheme/packages/ui/src/blocks.ts)).

Approvals are not tool rows. They are a **card stack at the bottom of the thread**, at most 36rem wide. The next card peeks 7px behind at 96% scale. The command card has a small "Command" header, the command in mono, and right-aligned buttons: Reject, an "Always allow…" dropdown that includes "Allow this session", and a primary **Run ↵**. Enter clicks Run and Escape clicks Reject from an empty composer. Holding a key never auto-approves the next card ([approval.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/assistant-ui/tool/approval.tsx), [approval-keys.ts](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/lib/keybinds/approval-keys.ts)). Pheme's equivalent choices are `once`, `chat` and `deny` ([protocol.ts](file:///home/user/pheme/packages/server/src/protocol.ts)). These map to Run, "Allow this session" and Reject. "Always allow" needs a persistent pattern list that Pheme does not have, so the port should hide it. Hermes does the same when a backend sets `allowPermanent: false` ([prompts.ts](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/store/prompts.ts)).

Reasoning is a "Thinking" disclosure. It shimmers with a timer while live. It shows a 10rem auto-following preview of small grey markdown. It then settles to "Thought for 12s", "Thought briefly" or "Thought" ([message-parts.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/assistant-ui/thread/message-parts.tsx)). Hermes only renders it when reasoning text is visible. The composer is a floating `rounded-2xl` box with a hairline ring and a translucent fill. Its left side has a "+" menu. Its right side has a model pill, a reasoning pill, and a round foreground-coloured send button that turns into a stop square while busy. Todos, queue and sub-agents sit in a **status stack** card above it ([composer/index.tsx](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/app/chat/composer/index.tsx)).

Several Hermes behaviours need backend features Pheme should not fake. These are branch in new chat, restore checkpoint, edit with rewind, the branch pickers, emoji reactions, read aloud and voice. The plan skips them. Retry can resend the last prompt. Copy, turn duration and queue work client-side.

## Copilot can back the reasoning, progress and todo UI, but only a real run proves it

Pheme's protocol has 13 event types. Its engine maps only message deltas and messages, tool start and end, `subagent.*`, errors, `usage_info`, idle and permission callbacks ([copilot.ts](file:///home/user/pheme/packages/server/src/copilot.ts)). The pinned SDK, `@github/copilot-sdk` 1.0.34, defines more events in its type files. These include `assistant.reasoning`, `assistant.reasoning_delta`, `assistant.intent`, `assistant.usage`, `tool.execution_progress`, `tool.execution_partial_result`, `tool.shell_output`, `session.todos_changed`, `session.title_changed` and `session.compaction_*` ([SDK tarball](https://registry.npmjs.org/@github/copilot-sdk/-/copilot-sdk-1.0.34.tgz)). The SDK also has `SessionConfig.reasoningEffort`. It applies only to models whose capabilities say they support it, and `ModelInfo.supportedReasoningEfforts` lists the allowed levels. Pheme passes no effort today, and its earlier "no reasoning menu" stance no longer holds.

Types alone are not proof. Pheme pins Copilot CLI 1.0.112 because SDK 1.0.34 speaks protocol 3 and newer CLIs speak protocol 4 ([DECISIONS.md](file:///home/user/pheme/docs/DECISIONS.md)). Whether that CLI emits reasoning, intent, shell output and todo events for the owner's models is unknown. The owner's quota is the Free tier, so the checks must stay at two or three short requests. The checks should be a small probe script that attaches a listener to every session event and writes raw event types and one sample payload each to a JSON file. That file then becomes the fixtures for the fake engine. The needed checks are:

1. A listing of models to read `supportedReasoningEfforts` and `defaultReasoningEffort`. This costs no chat turn.
2. One short turn on a reasoning-capable model with `reasoningEffort` set. It records whether `assistant.reasoning_delta` and `assistant.reasoning` arrive.
3. One short turn that asks for a three-step plan, one `ls` and one file edit. It records `assistant.intent`, `session.todos_changed`, `tool.execution_progress`, `tool.shell_output`, `tool.execution_partial_result`, the real tool names (the Hermes mapping assumes `bash`, `view`, `edit` and `create`, which is unverified), the shape of edit arguments (to synthesise a unified diff), `session.title_changed` and `assistant.usage`.

Each result decides one UI piece. If reasoning never arrives, ship the Thinking component but hide it, and drop the effort pill for models without effort support. If todos never arrive, hide the status-stack todo group. If shell output is absent, show the final result only.

| Hermes UI | Verdict for Pheme |
|---|---|
| Streaming transcript, tool rows, sub-agent cards, approval card, context meter, model pill | Back now. Restyle and port. |
| Reasoning disclosure, effort pill, intent ticker, todo group, live shell output, auto titles, per-turn usage | Build after the probe confirms the events. Add new protocol events. Do not persist deltas. |
| Approval-mode menu in the status bar | Back now through the existing `autoApproveAll` setting. |
| Queue, stop, steer | Already in Pheme. Restyle only. |
| Branch, restore checkpoint, edit-with-rewind, reactions, voice, read aloud | Skip. |
| Providers and keys, billing banners, gateways, bots, webhooks, pairing, profiles, plugins, MCP manager, system page, terminal, preview pane, pets, Starmap | Skip. Show no nav entry. |
| Dashboard Analytics and Logs | Stub as a read-only usage card and a log tail from the existing doctor output, or skip. |

The "stub or skip" rule needs one policy. If a Hermes control has no Copilot backing, **leave it out of the nav and out of the DOM**. A dead button makes the UI feel fake, which is the opposite of the owner's goal. One exception is where the layout depends on the slot. There, keep the slot and its spacing so the layout does not shift when the feature arrives.

## Test selectors have to come before any restyle

Pheme's source has **zero `data-testid` attributes**. Its Playwright smoke spec selects by class: `.bubble.user`, `.assistant`, `.sidebar-wrap`, `.menu-btn`, `.shell.drawer-open`, `.diff .dl.add`, `.commit-done`, `.branch-pill` and others ([smoke.spec.ts](file:///home/user/pheme/e2e/smoke.spec.ts)). About 10 unit-test files also use `querySelector` or class checks, while 23 `.tsx` tests query by role, text or label. A Tailwind restyle renames or deletes every one of those classes. It would break e2e at once and hide real regressions among the noise. Adding stable `data-testid` and role selectors first is cheap, since the codebase is about 40 files. It keeps the 626 unit tests and 13 browser tests usable as a safety net during the port ([PROGRESS.md](file:///home/user/pheme/PROGRESS.md)). Hermes itself uses Playwright with visual snapshots (`test:e2e:visual`), so the same tool can serve as the "exact match" gate. The reference must be real Hermes. The research did not run Hermes, so the owner needs to capture 6 to 8 reference screenshots of the states in the plan from the running desktop app. Because the UI font is the system font, screenshots from different operating systems will not match pixel for pixel. A tolerance, or a same-OS reference, is needed.

## What is still unknown

Hermes was read, not run. Two claims need a check against a running Hermes. First, the shadcn enter and exit classes on menus and dialogs (`animate-in`, `zoom-in-95`) may be inert, because `tw-animate-css` does not appear to be imported by the desktop build. If so, Hermes menus open without a zoom, and Pheme should not add one ([menu.ts](https://github.com/NousResearch/hermes-agent/blob/5688461d66fadd3ce3d6ed6bccccd958c7370eae/apps/desktop/src/components/ui/menu.ts)). Second, tooltip timing (200ms delay, no entrance animation) comes from DESIGN.md, not from observation. Bundle growth is estimated. The count of Hermes files needed once transitive `@/` imports are included was not computed, so a dependency walk should be the first task inside each porting item. Pheme's docs disagree with themselves on whether Changes is a dialog or a right column (DECISIONS line 72 against `changes-shell.png`), so the Changes item must check the code first.

## Conclusion

The research changes the framing. The gap to Hermes is not a missing design idea. It is a missing set of **small numbers and a missing runtime**: a 110% text scale, 28px rows, 2px radii, a 180ms enter slide, a 0.67-opacity scaffold, a sticky prompt, a bottom approval stack, and real icons. Those numbers live in files Pheme is now allowed to copy. Pheme's old rule against copying code was the largest single cause of the drift, so changing the docs is a real first step and not paperwork.

The owner's decision to include only what Copilot can support is cheap to honour for tool rows, approvals and the model pill. It is conditional for reasoning, todos and shell output. Those depend on what CLI 1.0.112 actually emits. The three-request probe should therefore run early and in parallel with the visual work. Its fixtures will let every later item be tested in fake mode with no further quota use.
